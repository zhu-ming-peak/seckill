## 从干净目录使用

克隆并切换交付标签后，按 README 的环境准备、数据库初始化、Redis/MQ 安装、测试、构建、运行顺序操作。初始化只新建独立实验数据及账户，不会自动重置演示库存。生成的应用连接文件默认在项目之外；也可用 LAB2_ENV_FILE/--env-file 指定自己的仓库外路径。

测试需要真实 MySQL、Redis、Broker。运行测试前先停用同一实验库的演示应用，避免后台任务读取测试请求。仅编译打包可执行 `python scripts/lab.py build`，不要求数据库服务运行；没有执行测试时不能据此宣称测试通过。

ECS 安装器是 Ubuntu 22.04、本实验已有服务器的具体实现，不能当作任意服务器的通用安装器。源码不包含 SSH 登录方式、真实地址或应用密码，使用者需自行准备已有资源并核对运行环境。

## 可审阅材料与范围

- sql/：表结构、演示数据、基础 CRUD/事务与检查、异步请求表；重置 SQL 不自动执行。
- .env.example：变量清单，不含真实值；本机脚本使用项目外 JSON 注入环境。
- src/：Java 源码、页面及集成测试；tests/、scripts/：HTTP、性能与运行辅助工具。
- deploy/：WSL 与 ECS 安装配置；docs/：分阶段设计、云产品学习和实测分析。
- docs/阶段E结果/：正式性能汇总与图表；逐请求原始日志、截图、服务器核查等材料在本地课程目录留存，报告选用关键证据。

38 项测试与阶段 E 的性能结果来自此前实际运行，ECS 功能结果来自阶段 F。本阶段交付检查不冒充重新完成整套性能测试；干净目录的构建与启动结果另记在阶段 G 完成记录。ECS 自建 MySQL 不代替仍待资源的 RDS 实践。

仓库未附加开源许可证。报告应同时注明仓库链接、标签、实验环境、测试条件及限制，不把仓库公开、云端页面可访问或一次构建成功等同于生产可用。
